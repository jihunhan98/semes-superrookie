# ReqOps — 요구사항 검토 및 산출물 관리

요구사항 등록, AI 본문 검토, 개발 이슈·산출물 생성, 산출물 검토·전체 확정을 관리합니다. 최신 작업 브랜치는 `semes`입니다.

## 현재 화면

| 단계 | 기능 |
|---|---|
| 1. 등록 | 요구사항 ID·본문·요청자 저장 |
| 2. 검토·확정 | 본문 검출 항목, 수정 초안, 고객 합의, 요구사항 버전 관리 |
| 3. 이슈·산출물 도출 | 개발 이슈와 SWVOC·기능 요구사항·비기능 요구사항·Detail Design 생성 |
| 4. 산출물 검토·전체 확정 | Jira 스타일 상세 창에서 개발 이슈·산출물 4종 전환, 본문 수정, 저장·개별 검토 완료, 전체 확정 |

4단계는 이슈와 연결 산출물을 목록에 보여줍니다. 항목을 열면 중앙에 작성 양식, 오른쪽에 상태·관련 요구사항·기한·원문이 표시됩니다. 저장하지 않은 수정 내용이 있으면 문서를 닫거나 전환할 때 확인합니다. Atlaskit 설치나 실제 Jira 연결 없이 기존 React 화면에 Jira 스타일을 적용했습니다.

`frontend/dist/standalone`에는 실행용 빌드가 포함됩니다. 기존 `run-all.bat` 실행 방식으로 사용할 수 있고, 사용자 PC에서 npm 설치나 프론트 빌드를 할 필요가 없습니다. AI 서버·백엔드는 변경된 소스로 다시 시작해야 합니다. 배포본에는 암호화키를 넣지 않으며 실행 시 생성합니다.

## 2026-10-19 변경

기존 **변경 영향 · 코드 근거** 기능을 제거했습니다.

- 사이드바 메뉴, 별도 화면, 상단 영향 알림 및 폴링 제거.
- 등록·수정·확정 시 기존 영향 분석 작업 생성과 관련 API 제거.
- 소스 업로드·파싱·클래스/메서드 등록·코드 스냅샷 검증 제거.
- 산출물 생성·확정에서 코드 등록 필수 조건 제거. Detail Design은 요구사항에 기반한 **개념 설계 제안**이며 실제 구현에서 확인된 클래스·호출 관계라는 뜻이 아닙니다.

기존 본문 검토와 산출물의 요구사항 원문·수치 검사, 누락 검토는 유지합니다. 누락 검토 API는 `/api/projects/{projectId}/artifact-review/coverage/{reqId}`로 분리했습니다. 폐기된 종류의 대기 작업은 AI 호출 없이 종료합니다. DB 스키마·기존 요구사항 본문·로컬 서버 설정은 변경하지 않습니다.

## 새 요구사항 간 알림 — 설계안

[UI·UX 설계](docs/requirement-conflict-notifications.md)와 [화면 시안](docs/screens/requirement-check-design.html)을 작성했습니다. 새 알림의 API와 실제 화면 연결은 아직 구현하지 않았습니다.

- REQ01~REQ10 중 REQ03 수정: 저장한 REQ03과 나머지 9개 전체를 비교합니다.
- REQ11 추가: 신규 REQ11과 기존 10개 전체를 비교합니다.
- 기준 불일치, 동작 상충, 의미가 불분명해 함께 확인할 항목을 알립니다.
- 양쪽 원문·ID·확인 이유·구체적인 조건을 한 화면에서 보여줍니다.
- 이번 범위는 알림 확인까지입니다. 요구사항 자동 수정·수정안 적용·승인·해결 관리는 포함하지 않습니다.

## 검증

- 프론트: `cd frontend` 후 `npm run typecheck`, `npm test`, `npm run test:e2e`, `npm run build:offline`.
- AI 서버: `cd ai-model` 후 테스트 환경에서 `AI_PROVIDER=rule python -m pytest tests -q`.
- 백엔드: `cd backend` 후 `./mvnw clean test` (JDK 21).
