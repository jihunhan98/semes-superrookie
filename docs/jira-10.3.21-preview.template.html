설명

원문 근거, 변경 범위, 완료 조건을 개발 이슈에 함께 정리합니다.

현상

고객은 여러 AMR 후보가 있을 때의 선정 기준과 선정 결과의 추적 가능성을 요구하고 있습니다. 기존 구현의 구체적인 동작은 제공되지 않았으므로 확인이 필요합니다.

개선 요구

VCS는 IDLE 상태이고 SOC 기준을 만족하는 AMR을 후보로 조회한다. 후보별 경로 거리를 비교해 가장 가까운 AMR을 선택하고, 거리가 같으면 SOC가 높은 AMR을 선택한다.

변경 범위

  • AMR 상태·SOC에 따른 후보 필터링
  • 경로 거리 오름차순, 동일 거리에서 SOC 내림차순 정렬
  • 선택 결과와 선정 근거를 이력 기록 기능에 전달

제약 조건·확인 사항

원문에 없는 기준은 확정하지 않았습니다

SOC 임계값, 거리 산정 방식, 거리·SOC가 모두 같은 경우의 우선순위, 후보가 없는 경우의 처리는 고객 확인이 필요합니다.

변경 전 / 변경 후

구분내용
변경 전기존 매칭 로직·소스 미제공. 현재 동작 확인 필요.
변경 후IDLE·SOC 적합 후보에서 최단 거리 우선 선택. 동일 거리이면 SOC가 높은 후보 선택.

완료 조건

  1. IDLE 상태가 아닌 AMR은 후보에서 제외된다.
  2. SOC 기준을 만족하지 못하는 AMR은 후보에서 제외된다.
  3. 최단 거리 후보가 선정되며, 동일 거리에서는 SOC가 높은 후보가 선정된다.
  4. 미정 기준·예외는 합의 후 해당 테스트에 반영한다.

도출 근거 · REQ-011

“후보별 경로 거리를 계산하고, 최단 거리 우선으로 선택하되 동일 거리이면 SOC가 높은 AMR을 선택한다.”

이슈로 묶은 이유: 후보 필터링과 우선순위 비교는 하나의 선정 결과를 만드는 연속 동작입니다. 이력 저장은 별도 이슈 VCS-143의 책임으로 나눴습니다. 이 분할은 설명용 예시입니다.

개요·선행 조건

VCS가 매칭 요청을 수신하면 현재 AMR 상태와 SOC, 후보별 경로 거리를 이용해 한 대의 AMR을 선정합니다. AMR 상태 정보와 SOC 기준이 사용 가능해야 합니다.

시나리오조건기대 동작

대안 흐름경로 거리가 같은 후보가 여러 대SOC가 높은 AMR 선정

VCS는 IDLE 상태이며 SOC 기준을 만족하는 AMR 후보를 조회한다. 후보별 경로 거리를 계산하고, 최단 거리 우선으로 선택하되 동일 거리이면 SOC가 높은 AMR을 선택한다. VCS는 선택 결과와 선정 근거를 매칭 이력으로 기록한다.

Jira 10.3 계열의 AUI 9.12 안내를 기준으로 라이브러리를 고정했습니다. 회사 10.3.21에 포함된 정확한 AUI 패치 버전은 확인하지 않았습니다. Jira 제품 버전과 AUI 버전은 서로 다른 번호입니다.

버전 번호만으로 사내 플러그인, 워크플로, 커스텀 필드, 화면 구성, 문서 템플릿을 알 수 없습니다. 이 예시는 해당 설정을 재현했다고 주장하지 않습니다.

CSS·JavaScript·아이콘 폰트가 이 파일 안에 포함되어 있습니다. npm 설치·CDN·Jira 로그인 없이 열 수 있습니다. 라이브러리 원문·라이선스 고지는 파일 내부와 함께 제공한 문서에 있습니다.
