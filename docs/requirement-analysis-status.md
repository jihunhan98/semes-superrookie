# 요구사항 검토: 200 응답과 분석 상태

`POST /analyze`의 HTTP 200은 응답 전달 성공을 뜻한다. AI 모델 응답 파싱·원문 위치·상충 근거 검증과 기존 요구사항의 모든 배치 검토가 완료되었는지는 `reviewStatus`로 확인한다. 모델 호출 실패나 결과 검증 실패 시 규칙 검토 결과를 보존하므로 HTTP 200과 `PARTIAL`이 함께 반환될 수 있다.

기존 화면은 `PARTIAL`을 전체 실패와 같은 문구로 표시하고 제안 버튼까지 비활성화했다. 후보 앞의 원은 실제 라디오 입력이 아닌 장식 요소였으며, AI 설명을 일반 텍스트로 출력해 마크다운 표 구분선이 그대로 나타났다.

## 변경 동작

- 파싱 실패뿐 아니라 원문·수정안 검증 실패에도 전체 요청 문맥을 유지해 한 번 재요청한다. 두 번 실패하면 불완전 상태를 유지한다.
- `reviewWarnings`를 AI 응답 → 백엔드 저장된 검토 문맥 → 화면에 전달한다. 본문과 자격 증명은 오류 로그에 남기지 않는다.
- `PARTIAL`에서도 반환된 제안의 선택·반영·직접 수정·원문 유지가 가능하다. 최종 확정은 기존처럼 완전한 재분석을 요구한다.
- 라디오를 선택하면 후보만 바뀌고, ‘AI 제안 반영하기’를 눌러야 최종 본문이 바뀐다.
- 변경 이유·해석·제안 안내·수정안은 GFM 마크다운으로 표시한다. 표는 가로 스크롤을 지원한다. 원문 인용과 실제 저장되는 본문은 원래 문자열을 유지한다.

| 코드 | 의미 |
| --- | --- |
| INVALID_RESPONSE | JSON 또는 응답 형식 검증 실패 |
| INVALID_FINDING | 원문 위치·필수 판단 근거·수정안 또는 상충 근거 검증 실패 |
| TIMEOUT | 모델 응답 대기시간 초과 |
| BATCH_FAILED | 그 밖의 배치 처리 실패 |
| SOURCE_TOO_LONG | 규칙 검토가 처리할 수 있는 구절 길이 초과 |

기존에 저장된 검토에는 원인 코드가 없다. 구체적인 원인을 기록하려면 변경된 AI 서버와 백엔드를 재시작한 후 ‘AI 다시 분석’을 실행한다. DB 스키마 변경은 없다. 폐쇄망 실행에는 갱신한 `frontend/dist/standalone`을 사용한다.
