# 산출물 검토 화면

대상: `/projects/{projectId}/requirements/{requirementId}/review`

요구사항 검토 페이지의 서체, 파란색 강조, 흰색 카드, 테두리, 상태 배지, 하단 확정 버튼을 이어서 사용한다. Jira 등록 설정과 이슈 생성 동작은 이 검토 화면에서 제거했다. 저장된 개발 이슈·산출물 API와 전체 확정 API를 사용한다.

| 영역 | 동작 |
| --- | --- |
| 상단 현황 | 개발 이슈 수, 실제 생성된 문서 수/예상 수, 생성·검토·확정 단계 표시 |
| 왼쪽 목록 | 이슈 ID·제목 검색, 선택 상태, 문서 4종의 생성 여부 |
| 오른쪽 본문 | 개발 이슈와 SWVOC·기능·비기능·상세 설계를 탭으로 전환 |
| 개발 이슈 | 현상·개선 요구·변경 범위·제약 조건과 변경 전/후 비교 |
| 문서 | Markdown 표·목록·강조, 시나리오별 선행 조건·수행 흐름·완료 조건 |
| 상세 설계 | 클래스 구조와 변경 전·후 시퀀스, 확대·축소, 전체 보기, 이미지 복사 |
| 원문 근거 | 해당 이슈의 인용 구절 및 확정 요구사항 전체 펼치기 |
| 하단 | 이전/다음 이슈, 현재 내용을 전체 확정, 확정 후에도 문서 열람 |

생성 수는 검토 완료 수를 뜻하지 않는다. 미생성 문서는 탭에서 안내하고, 전체 확정은 모든 문서가 준비된 뒤 가능하다. 조회 실패는 오류와 다시 불러오기 버튼을 제공한다. 문서 캐시는 이슈·산출물 ID·종류·리비전으로 구분하며, 빠르게 탭을 전환할 때 이전 요청이 현재 문서를 덮어쓰지 않도록 한다. 기존 `?issue=...`, `?issueKey=...`, `?artifact=...` 링크를 유지한다.

v2 시퀀스 필드와 기존 `sequenceBeforeCode`/`sequenceAfterCode`를 모두 지원한다. 클래스 배열은 이름·필드를 보존해 Mermaid 클래스로 변환한다. `legacyExtras`·quality 같은 내부 구조를 본문 필드 이름으로 노출하지 않는다. 유의미한 추가 업무 내용은 참고 내용에 남긴다. 다이어그램 문법 오류 시 저장된 코드를 확인할 수 있다.

타입 검사·단위 테스트 32개·폐쇄망 빌드를 확인했다. DOM 통합 검증으로 탭 전환, 딥 링크, 표, 시나리오, 재조회, 늦은 응답, 확정 후 열람을 확인했으며 실제 Mermaid 파서로 기존/신규 클래스·시퀀스 문법을 검사했다. 실행 환경의 Chromium IPC 제한과 클라우드 브라우저의 localhost 접근 제한으로 실제 화면 스크린샷 검증은 수행하지 못했다.

배포는 갱신된 `frontend/dist/standalone`으로 프런트엔드를 재시작한다. DB·백엔드·AI 서버 변경은 없다.
