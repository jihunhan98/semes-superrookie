# 개발 이슈·산출물 UI — Jira Data Center 10.3.21 기준

실제 화면에 기존 고정 양식을 적용했다. Jira Data Center **10.3.21**의 UI 계열에 맞춰 공식 **AUI 9.12.0 CSS·아이콘 폰트**를 저장소에 포함했다. UI 양식은 기존 백엔드 스키마와 AI 생성 프롬프트를 기준으로 유지하며, 이전 HTML의 설명용 업무 데이터를 실제 화면에 넣지 않는다.

## 고정 양식

| 문서 | 본문 순서 |
| --- | --- |
| 개발 이슈 | 현상 → 개선 요구 → 변경 범위 → 제약 조건 → 변경 전·후 비교 |
| SWVOC | 요청자 → 고객 요청 내용 → 특이 사항 |
| 기능 요구사항 | 요구사항 개요 → 제약 조건 → 기본·변형·예외 동작 |
| 비기능 요구사항 | 요구사항 개요 → 제약 조건 → 기본·변형·예외 동작 |
| 상세 설계 | 설계 개요 → 클래스 다이어그램 → 변경 전·후 시퀀스 다이어그램 |

기능·비기능의 각 동작은 **선행조건 / 시나리오 / 후행조건** 표로 표시한다. 적용·확인 필요·해당 없음과 사유를 함께 보여준다. 값이 비어 있어도 정해진 항목은 유지한다. 개발 이슈의 변경 전이 비어 있으면 기존 요청대로 ‘없음’을 표시하며 저장 데이터는 바꾸지 않는다.

양식 근거는 `IssueDto`, `ArtifactContentValidator`, `ArtifactService.emptyV2`, `ai-model/main.py`의 `_VOC_PROMPT`·`_FUNCTIONAL_PROMPT`·`_NONFUNCTIONAL_PROMPT`·`_DETAIL_DESIGN_PROMPT`다. 회사 Jira의 별도 화면 구성·플러그인·테마·필드는 버전 번호만으로 확인할 수 없으므로 사내 화면과 완전히 같다고 가정하지 않았다. Jira 제품 버전과 AUI 라이브러리 버전은 다르며, 회사 인스턴스의 정확한 AUI 패치 버전은 확인하지 않았다.

## 화면과 동작

대상은 `/projects/{projectId}/artifacts`와 `/projects/{projectId}/requirements/{requirementId}/review`다. 기존 상세·산출물 URL은 검토 화면으로 연결하는 동작을 유지한다.

- 프로젝트 산출물 목록: 검색·확정 여부 필터, 요구사항 ID·본문·상태·버전·담당자·수정일을 표로 표시한다.
- 왼쪽: 개발 이슈 ID·제목 검색, 선택 상태, 산출물 4종 생성 여부.
- 본문 상단: 이슈 ID·제목·상태, 원문 근거 펼침, 본문 넓게 보기, 이슈 도출 화면 이동.
- 본문: 개발 이슈·SWVOC·기능·비기능·상세 설계의 탭. 공식 AUI 탭 구조와 상태·버튼·표·안내 메시지 스타일을 사용한다.
- 오른쪽: 실제 데이터의 문서 상태·리비전·프로젝트·근거 요구사항·관계자·날짜·연결 문서. 좁은 화면에서는 본문 아래로 이동한다.
- 하단: 이전·다음 이슈, 전체 확정. 생성이 끝난 문서와 확정한 문서는 계속 열어볼 수 있다.

본문 넓게 보기는 이슈 탐색과 상세 정보를 접어 표·설계를 크게 읽게 한다. 본문은 페이지와 함께 스크롤하며 작은 높이의 입력창에 가두지 않는다. 탭은 방향키·Home·End를 지원한다. 이슈·탭 선택은 URL에 반영되어 새로고침·직접 링크에서 복원된다.

조회 실패는 다시 불러오기로 복구하며, 미생성 문서는 별도 안내한다. 캐시는 이슈·산출물 ID·종류·리비전으로 분리하며 늦은 응답이 현재 문서를 덮어쓰지 않도록 한다. 생성·재시도·전체 확정 API와 확정 조건은 기존 동작을 유지한다. 새 Jira 등록·연동 설정·첨부파일 기능을 추가하지 않았다.

## 이전 데이터와 다이어그램

JSON 속성 순서에 의존하지 않고 문서 유형별 고정 순서로 렌더링한다. 이전 `request/notes`, `description/constraints`, `behaviors`, `sequenceBeforeCode/sequenceAfterCode`, 클래스 배열을 함께 읽는다. v2의 빈 필드와 `legacyExtras` 안의 기존 업무 내용이 함께 있어도 기존 값을 보존해 표시한다. 명시적으로 ‘해당 없음’인 동작에 옛 시나리오를 되살리지 않는다.

`legacyExtras`, `quality`, `engine`, `schemaVersion`, 응답 시간 같은 내부 이름은 본문 필드로 노출하지 않는다. 역할·목적 등 인식 가능한 기존 업무 내용은 ‘추가 업무 내용’에 남긴다. 클래스·시퀀스의 확대·축소·전체 보기·이미지 복사는 기존 Mermaid 표시 기능을 유지한다. 실제 클래스나 변경 전 근거가 없으면 기존 저장된 확인 안내를 표시한다.

## 공식 AUI와 폐쇄망 배포

공식 배포 원문은 `frontend/app/components/jira/aui-9.12.0.source.css`에 보존했다. `frontend/scripts/scope-aui.mjs`가 SHA-256을 확인한 뒤 선택자를 `.jira-dc-ui` 내부로 제한하고 폰트 URL을 로컬 파일로 바꾼다. 출력은 `aui-9.12.0.scoped.css`다. 다른 요구사항·로그인 화면에 AUI 초기 스타일이 번지지 않게 한다.

Next.js의 탭·넓게 보기·재조회·확정 동작은 React가 처리한다. 전역 DOM을 수정하는 jQuery·AUI JavaScript 초기화 코드는 앱에 주입하지 않는다. AUI CSS·폰트는 서버가 로컬로 제공하며 CDN이나 npm 설치 없이 배포본에서 사용할 수 있다. 라이선스는 `frontend/public/vendor/aui-9.12.0/LICENSE.txt`에 포함했다.

```bash
cd frontend
npm ci
node scripts/scope-aui.mjs
npm run typecheck
npm test
npm run build:offline
```

회사 PC에서는 기존처럼 `run-all.bat`으로 새 `frontend/dist/standalone`을 실행한다. DB·백엔드·AI 서버 변경은 없다.

## 검증

- 타입 검사 통과.
- 단위 테스트 36개 및 기존 경로 검사 통과.
- 고정 양식의 빈 필드·순서·이전 스키마·명시적 제외·내부 메타데이터 비노출 회귀 검사 통과.
- DOM 통합 검사: 5개 탭, 키보드 이동, 표·다이어그램 연결, 원문 펼침, 넓게 보기, 이슈 이동, 조회 실패·재조회, 늦은 응답, 확정 1회 호출, 확정 후 열람, 직접 링크 복원 통과. Mermaid UI는 DOM 검사에서 대역으로 분리했다.
- 공식 AUI의 2,718개 선택자가 화면 내부로 제한되어 있음을 검사했다.
- 이 환경의 브라우저 실행·로컬 파일 열기 제한 때문에 실제 화면 스크린샷과 시각적 배치는 확인하지 못했다.

빌드·배포본 검증 결과는 이번 커밋의 실행 결과를 따른다.
