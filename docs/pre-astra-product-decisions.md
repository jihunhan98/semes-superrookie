# Astra 계획 수립 전 제품 결정사항

이 문서는 상세 개발 계획을 작성하기 전에 사용자와 확정한 제품 흐름, UI/UX, 자동화 범위를 기록한다.

## 1. 확정된 방향

### 기존 기능 보존 결정

다음 기존 기능은 새 4단계 UX에서도 유지한다.

- 전체 요구사항 목록과 요구사항 상세
- 고객 합의 기록
- 요구사항 버전 이력과 버전 간 변경 비교
- AI 개발 이슈 분할과 사람의 분할안 수정
- 요구사항 ↔ 개발 이슈 추적
- 개발 이슈 고정 양식
- SWVOC 고정 양식
- 기능·비기능 요구사항 고정 양식
- Detail Design 고정 양식
- 산출물 일괄 자동 생성
- 예외 중심 검토와 전체 확정

AI 검토·재분석과 상태·보류 처리는 기능과 데이터는 유지하되 UI를 간소화한다.

- AI 검토 결과를 별도 보고서처럼 길게 노출하지 않고 원문 안의 검출 위치와 결정 질문 중심으로 보여준다.
- 내부 상태값과 전이 이력은 유지하되 사용자가 매 단계마다 상태를 직접 조작하지 않도록 한다.
- 모듈 전용 필드는 사용하지 않는다. 개발 이슈의 `변경 범위`는 특정 모듈 체계에 종속되지 않는 자유 형식으로 유지한다.

### 사용자에게 보이는 전체 흐름

1. 요구사항 등록
2. AI 검출 결과 수정
3. 요구사항 확정 후 산출물 도출
4. 산출물 검토 후 전체 확정

프로젝트 맥락 수집, 유사 요구사항 검색, 충돌 검사, 개발 이슈 분할 초안 생성, 산출물 생성, 일관성 검사는 위 4단계 사이의 백그라운드 작업으로 처리한다.

### 요구사항 등록

- 사용자는 제목과 고객 요구사항 원문을 입력한다.
- 회의록, 기존 문서, 화면 자료는 선택적으로 첨부한다.
- 사용자가 처음부터 완성된 요구사항 문서를 작성하도록 요구하지 않는다.

### AI 검출과 수정

- AI 검토 보고서 전체를 별도 문서로 보여주지 않는다.
- 원문의 애매한 구절과 충돌 지점을 직접 표시한다.
- 구현 결과를 바꾸는 미확정 사항만 질문한다.
- 프로젝트 자료에서 확인 가능한 내용은 자동 반영한다.
- 수치와 정책을 근거 없이 생성하지 않는다.

### 개발 이슈

- AI가 요구사항을 기본적으로 N개의 개발 이슈로 분할한다.
- 사용자는 기본 분할안을 그대로 사용할 수 있다.
- 필요한 경우에만 이슈를 합치거나 나누고 제목을 수정한다.
- 확정된 개발 이슈는 원 요구사항과 자동 연결한다.

### 산출물

각 개발 이슈에는 다음 산출물 4종을 연결한다.

1. SWVOC
2. 기능 요구사항
3. 비기능 요구사항
4. 상세 설계

- 요구사항과 개발 이슈가 확정되면 산출물 4종을 일괄 생성한다.
- 산출물마다 별도로 `AI로 채우기` 버튼을 누르게 하지 않는다.
- 상세 설계의 시퀀스 다이어그램은 사람이 이해하기 쉬운 업무 언어로 표현한다.

### 산출물 검토

- 문서 전체보다 정책 충돌, AI 해석, 변경점, 근거 부족 항목을 먼저 보여준다.
- 필요할 때 개발 이슈와 산출물 전문을 열어 상세 검토한다.
- 요구사항 본문을 산출물 화면에서 함께 참고할 수 있어야 한다.
- 개발 이슈와 산출물의 연결 상태를 한 화면에서 확인한다.
- 최종 승인은 전체 작업 묶음에 대해 한 번 수행한다.

### 지식 축적

- 사용자가 별도의 지식 베이스 입력 화면에 반복해서 내용을 작성하지 않는다.
- 확정된 요구사항, 개발 이슈, 산출물, 사용자 결정 이력을 프로젝트 지식으로 자동 축적한다.
- AI는 다음 요구사항 처리 시 이 기록을 참고한다.

## 2. 다음으로 확정할 항목

### A. AI 검출 결과의 종류와 사용자 행동

- 반드시 답해야 하는 차단 질문과 참고 경고를 구분할지
- AI가 자동 반영한 내용을 어떤 방식으로 보여줄지
- 개발 이슈 분할안을 이 화면에서 함께 확정할지
- 고객 합의 기록은 유지한다. 이 단계의 본문, 별도 화면, 확정 창 중 어디에 배치할지 결정한다.

### B. 산출물 검토 방식

- 검토 홈에서 보여줄 요약 정보
- 개발 이슈와 산출물의 화면 배치
- 사용자가 직접 수정할 수 있는 범위
- 산출물별 확정과 전체 확정의 관계

### C. 실패와 재시도

- AI 분석 실패 시 요구사항 등록을 계속 허용할지
- 일부 산출물만 생성 실패했을 때의 표시와 재시도 방식
- 사용자가 작업 중 화면을 닫았다가 돌아왔을 때의 복구 방식

### D. 확정 후 변경

- 요구사항 변경 시 영향받은 개발 이슈와 산출물 표시 방식
- 기존 확정본 유지 및 새 버전 생성 방식
- 재생성 범위를 AI가 추천할지 사용자가 직접 선택할지

### E. 산출물 필드와 검증 규칙

- 산출물 4종의 최종 필드
- 필수값과 선택값
- 프로젝트 간 공통 형식과 프로젝트별 확장 범위
- 산출물 간 수치·용어·연결 관계 검증 규칙

## 3. 결정 순서

1. AI 검출·수정 화면 확정
2. 산출물 검토 화면 확정
3. 생성 진행·실패·재시도 확정
4. 확정 후 변경과 버전 관리 확정
5. 산출물별 필드 확정
6. 전체 클릭 흐름 최종 검토
7. Astra용 상세 개발 계획 작성

## 4. Astra에 전달할 최종 자료

- 확정된 클릭형 UI
- 이 문서의 최종본
- 화면별 입력, 출력, 버튼, 상태 전이
- 백그라운드 작업 목록
- DB에 영구 저장할 결정사항과 이력
- 현재 코드에서 유지, 통합, 제거할 영역
- 단계별 완료 조건과 테스트 시나리오
