# 슈퍼루키 프로젝트 발표 구성안

- 작성일: 2026-11-06
- 기준 브랜치: `semes`
- 분량: 표지 포함 9페이지 (최대 10페이지)
- 상태: 구성 검토안. PPT 파일은 구성 승인 후 제작한다.

## 발표 방향

**ReqOps — AI 기반 고객 요구사항 검토 및 개발 산출물 작성 지원**

고객 요구사항의 불명확한 부분을 개발 전에 확인하고, 정리된 요구사항으로 개발 문서 초안을 작성해 주는 AI 개발 지원 도구다.

신입사원 슈퍼루키 과제로서 업무에서 발견한 문제 → 직접 개발한 기능 → 회사 업무에 주는 도움 순서로 설명한다. 핵심은 요구사항의 모호함·누락·상충을 확인하도록 돕는 것과 반복적인 개발 문서 작성 부담을 줄이는 것이다.

## 핵심 내용 상세

### 요구사항 검토 기준

1. 동작 조건·수치·판단 기준이 불명확한지
2. 수행 주체나 중요한 예외 처리가 빠졌는지
3. 기존 요구사항과 상충하는지

각 항목은 원문, 확인이 필요한 이유, 구체적인 수정안을 함께 보여준다. AI 제안값은 확정된 업무 기준으로 표현하지 않고 담당자가 적용·수정·제외하도록 설명한다.

### 업무 예시 구성

`PROJECT.md`의 태스크 전개·전환 요구사항을 기반으로 ‘필수 요건’이라는 표현이 실제 구현·시험에서 어떤 추가 확인을 요구하는지 보여준다.

- 원문: 필수 요건이 충족된 경우 태스크를 재개한다는 취지의 요구사항
- 확인 항목: 단계별 필수 요건, 판단 주체, 미충족 시 처리
- 결과: 담당자가 기준을 확인한 뒤 구현·시험에 활용할 수 있는 문장으로 구체화

발표용 축약 문장과 보완 문장은 설명용 예시로 명시한다. 실제 AI 실행 결과나 고객과 확정한 기준으로 제시하지 않는다.

### 개발 이슈와 산출물

| 구분 | 주요 내용 |
| --- | --- |
| 개발 이슈 | 현상, 개선 요구, 변경 범위, 제약 조건, 변경 전·후 비교 |
| SWVOC | 요청자, 고객 요청 내용, 특이 사항 |
| 기능 요구사항 | 개요, 제약 조건, 기본·변형·예외 동작 |
| 비기능 요구사항 | 품질 속성에 대한 개요, 제약 조건, 기본·변형·예외 동작 |
| 상세 설계 | 설계 개요, 클래스 다이어그램, 변경 전·후 시퀀스 다이어그램 |

개발 이슈가 부모이며 그 아래 문서 4종이 연결된다. 상세 설계와 다이어그램은 개발자가 검토할 설계 초안으로 설명한다. 실제 코드에서 확인된 클래스·호출 관계로 단정하지 않는다.

## 제작 원칙

- 기능 설명과 실제 업무 예시에 가장 많은 비중을 둔다.
- 기술 스택은 8페이지에서 간단히 설명한다.
- 페이지마다 핵심 메시지 하나와 화면·도식 하나를 중심으로 구성한다.
- 기존 기획서의 ‘3시간 → 5분’은 실측 결과가 아니므로 성과로 사용하지 않는다.
- 측정 자료가 없으면 기대 효과와 측정 계획으로 표현한다.
- README와 DESIGN에는 과거 계획과 이후 구현 기록이 섞여 있으므로 최신 기능 문서를 우선한다.
- 저장소의 구현·테스트 기록과 실제 사내 LLM·Oracle·Jira 통합 실행 및 업무 적용 성과를 구분한다.
- 발표자 소속·이름과 실제 성과 수치는 확인된 정보만 입력한다.
