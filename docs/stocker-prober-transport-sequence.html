01. Job Step 전체 흐름

ASSIGNED→MOVE_TO_LOAD→LOAD→MOVE_TO_UNLOAD→UNLOAD

위는 제공된 기본 Step 목록입니다. 아래 상세 시나리오의 실제 보고 순서는 ASSIGNED → MOVE_TO_UNLOAD → UNLOAD → MOVE_TO_LOAD입니다.

02. 통합 시퀀스 다이어그램

요청 / 응답Step 변경설비 · 자재 이벤트VCS 내부 동작 (통신 메시지 아님)

메시지를 클릭하면 인터페이스 정의표의 해당 행으로 이동합니다.

주행 개시, 도킹 완료, 출고 알림 수신, 이적재 완료 등은 VCS 내부 동작으로 표시하며 송수신 메시지 화살표를 사용하지 않습니다.

03. 메시지 인터페이스 정의

No.구간송신 → 수신메시지의미 / 발생 조건

05. 확인이 필요한 항목

Step 및 메시지 의미 확인

① Stocker → Prober 반송에서 UNLOAD 완료 직후 MOVE_TO_LOAD로 전환하는 것이 실제 운영 규칙인지 확인이 필요합니다.

② VCS_INFORM_REP 및 AMOS_INFORM_RPT의 메시지 접미사(REP/RPT)는 일반적인 요청·보고 관례와 다르게 보일 수 있으나, 전달받은 명칭을 수정하지 않았습니다.

③ Prober 도킹은 별도 DOCKING 요청 없이 진행합니다. ④ LOAD 완료 응답은 전달받은 VCS_LOADCOMPLETE_REP 명칭을 그대로 사용했으며 실제 송신 측 메시지명 확인이 필요합니다.
