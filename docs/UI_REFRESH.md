# Tasks 스타일 UI 리팩토링

## 기준 및 범위

- 기준: main `bf4f149`, 작업 브랜치 `feat/tasks-ui-refresh-codex`.
- Next.js 14 / React 18 / TypeScript / CSS Modules. 신규 런타임 의존성 없음.
- 이번 단계: 공통 레이아웃 및 요구사항 목록. 실제 API 데이터 사용.
- 디자인: 흰 배경, 중립색, 얇은 테두리, 검정 주요 버튼, 상태별 보조색.
- 새 토큰은 `.ui-refresh`에 한정해 아직 이전하지 않은 화면에 영향을 주지 않는다.
- 기존 상세·검토·산출물 화면은 다음 단계에서 같은 공통 UI로 이전한다.

## 이번 단계 구현

- AppShell: 밝은 헤더, 프로젝트 내비게이션, 계정 메뉴, 모바일 dialog 메뉴.
- 공통 Button / PageHeader / StatusBadge / Icon / 로딩·빈 결과·오류 UI.
- 요구사항 표: ID / 내용 / 상태 / 버전 / 담당자 / 수정일.
- ID·내용·담당자 검색, 전체·진행 중·각 상태 필터, 담당자 복수 OR 필터.
- 열 정렬, 페이지당 10/20/50행, 첫/이전/다음/마지막 페이지.
- URL에 q/status/assignees/sort/direction/page/size 보관. 잘못된 값은 기본값 처리.
- 상세에서 브라우저 뒤로 가기 시 URL 복원. 쿼리 없는 목록 링크는 사용자·프로젝트별
  sessionStorage 값을 복원하며 명시적인 URL 쿼리를 우선한다.
- 모바일은 표 영역만 가로 스크롤. 본문 전체는 넘치지 않는다.
- 가짜 검색·알림 버튼, 일괄 작업 없는 체크박스, API에 없는 우선순위는 추가하지 않음.
- 미구현 추적성은 클릭 가능한 링크 대신 준비 중으로 표시.

## 검증

- Next.js 프로덕션 빌드 / TypeScript 검사.
- Chromium, API 응답 fixture 24건으로 화면·기능 검증:
  검색, 상태, 담당자 복수 선택, 정렬, 페이지 이동, 상세 왕복, 목록 링크 복원,
  빈 검색/빈 프로젝트, 범위 밖 페이지 보정, API 실패 후 재시도.
- 데스크톱 1440px / 모바일 390px. 모바일 메뉴 Escape 닫기와 트리거 포커스 복귀,
  계정 메뉴 Escape 닫기, 문서 가로 넘침 없음, 브라우저 런타임 오류 없음.
- 사내 Oracle/LLM에 연결한 통합 검증은 수행하지 않음. 기존 API 계약은 변경하지 않음.
- 새 standalone 빌드의 실행도 검증했으나, 생성된 서버 액션 암호화 키의 업로드가 자동 승인 검토에서 차단되어 배포 파일은 커밋에서 제외했다.

## 로컬 확인

```bash
git fetch origin
git switch --track origin/feat/tasks-ui-refresh-codex
```

이미 브랜치가 있으면 `git switch feat/tasks-ui-refresh-codex` 후 `git pull`.
프런트엔드 디렉터리에서 `npm ci`와 `npm run build` 후 `npm start`로 확인한다.
백엔드를 실행한 상태에서 로그인 → 프로젝트 → 요구사항으로 이동한다.
기존 `frontend/dist/standalone`은 이번 UI를 포함하지 않는다. 폐쇄망 배포 시 배포 환경에서
새 빌드를 생성해야 하며, 생성된 암호화 키는 저장소에 공개하지 않는다.

## 다음 구현 순서

1. 등록·상세 화면을 AppShell과 공통 폼으로 이전.
2. 검토·수정 화면: 본문/AI 검토 2열, 고객 합의 요약, 확정 조건 안내.
   AI 응답이 뒤늦게 도착해 사용자의 최신 입력을 덮어쓰지 않도록 처리.
3. 버전 이력: 비교 컨트롤 통일, 모바일 단일 열 비교.
4. 산출물: 요구사항 → 이슈 → 산출물 경로, 기존 실제 생성/편집/확정·Mermaid 유지.
5. 프로젝트·로그인·설정 이전 후 미사용 기존 스타일 정리.

고객 합의 후 본문 변경 시 확정 허용 여부는 기존 서버 구현까지 확인해 별도 항목으로
처리한다. 첨부파일 저장·초안 자동 저장·추적성 신규 개발은 이번 범위에 포함하지 않는다.

기존 `feat/tasks-ui-refresh` 브랜치에 별도 구현이 추가되어, 충돌을 피하고 비교할 수 있도록
이번 구현은 `feat/tasks-ui-refresh-codex` 브랜치로 분리했다.
