# 개발 이슈 상세화의 제목·원문 보존

2026-10-30 · `POST /issues/enrich`

## 수정한 문제

‘이슈 확정 및 산출물 4종 자동 생성’을 누르면 서버가 먼저 개발 이슈 상세 내용을 AI에 요청한다. 기존 구현은 AI가 반환한 제목·원문 구절을 입력값과 한 글자씩 비교하고, 응답 순서까지 같다고 가정했다. 사용자가 아무것도 변경하지 않아도 AI가 제목을 다듬거나 구절의 공백·순서를 바꾸면 `422 / 개발 이슈 근거가 변경되었습니다`로 중단됐다.

## 변경 후 처리

- 제목과 원문 구절은 서버가 입력값 그대로 보존한다. AI 응답에서 제목·구절을 다시 가져와 저장하지 않는다.
- 한 번에 여러 이슈를 요청할 때 서버가 `issueRef`를 붙인다. AI는 해당 식별자와 상세 본문만 반환하고, 서버는 식별자로 연결해 원래 순서를 복원한다.
- 이전 형태의 응답은 공백을 제외한 원문 구절이 유일하게 일치할 때만 연결할 수 있다. 모델이 바꾼 제목은 식별 근거로 사용하지 않는다.
- 식별자 누락·중복·알 수 없는 값, 이슈 누락, 본문 형식 오류가 있으면 이슈마다 대상 하나씩 자동 재요청한다. 재요청에도 전체 요구사항과 기존 요구사항 문맥을 그대로 넣는다.
- 단일 대상 요청은 다른 이슈와 연결될 가능성이 없으므로 AI가 재작성한 제목·구절을 버리고 상세 본문만 사용한다. 여러 이슈의 배열 위치만 믿고 본문을 연결하지 않는다.
- 개선 요구·변경 범위의 필수값, 문자열 형식, 근거 없는 수치·단위·경계 조건 검사는 유지한다. 생성 실패를 빈 본문으로 성공 처리하지 않는다.

백엔드가 받는 응답은 기존과 동일한 `issues` 목록이며 각 항목의 `title`, `quote`는 요청의 원본 값이다. 상세 본문 필드만 AI가 작성한다. DB와 프런트 API는 변경하지 않는다.

## 오류 구분

| 상황 | AI 서버 상태 | 안내 |
|---|---|---|
| 입력 제목이 비었거나 입력 구절이 요구사항에 없음 | 422 | 실제 입력을 확인할 항목 표시 |
| 자동 재요청 후에도 본문 생성·검증 실패 | 502 | AI가 상세 내용을 올바르게 작성하지 못했음을 표시 |
| 제공자 연결·설정 문제 | 503 | AI 서버의 상세화 실패 표시 |
| 제공자 응답 시간 초과 | 504 | 상세화 응답 시간 초과 표시 |

오류 응답은 `detail.message`에 원인을 담는다. 기존 백엔드가 이 값을 읽으므로 사용자 화면에도 해당 안내가 나온다. ‘사용자가 개발 이슈 근거를 변경했다’는 잘못된 안내를 생성하지 않는다.

## 적용 방법

최신 `semes`의 `ai-model` 소스를 받은 뒤 AI 서버를 재시작한다. 새 `issue_enrichment.py`도 함께 받아야 한다. 새 패키지 설치, DB 변경, 프런트 재빌드는 필요 없다. 서버 주소·키·로컬 설정은 변경하지 않는다.

## 검증 범위

API 테스트로 제목·인용 변경, 공백·줄바꿈 변경, 이슈 순서 변경, 식별자 누락·중복·알 수 없는 값, 자동 개별 재요청, 전체 문맥 보존, 잘못된 수치·필수값의 거절, 연결 실패·타임아웃 상태를 검사한다. 사내 LLM과 실제 운영 DB 연결 검증은 포함하지 않는다.
