# 기능명세서

표기: `FR-{기능}-{번호}`. 우선순위 P0(필수) / P1(중요) / P2(선택). 스택: Next.js → Spring Boot → Oracle.

---

## 1. 기능 1 — 로그인 · 프로젝트 관리

범위: 아이디(사번)·비밀번호 인증 + 프로젝트 생성/참여/설정. 세션·JWT·AI 미사용.

| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| FR-1-01 | 회원가입 | 이름·사번·부서·비밀번호로 계정 생성. 사번 중복 불가 | P0 |
| FR-1-02 | 로그인 | 사번·비밀번호 일치 확인만 (세션/토큰 없음) | P0 |
| FR-1-10 | 프로젝트 목록 | 내가 참여한 프로젝트 목록 | P0 |
| FR-1-11 | 프로젝트 생성 | 이름·고객사·설명·대상 모듈로 생성. 생성자=Owner, 접근 토큰 발급 | P0 |
| FR-1-12 | 프로젝트 참여 | 접근 토큰으로 Member 합류 | P0 |
| FR-1-13 | 프로젝트 열기 | 프로젝트 진입(이후 기능 2로) | P0 |
| FR-1-20 | 기본 정보 수정 | 이름·고객사·설명·대상 모듈 수정 (Owner) | P0 |
| FR-1-21 | 토큰 재발급 | 접근 토큰 재발급, 이전 토큰 폐기 (Owner) | P1 |
| FR-1-22 | 멤버 관리 | 멤버·역할 조회, 초대(토큰 공유) (Owner) | P1 |

데이터: User(사번·이름·부서·비밀번호해시) · Project(이름·고객사·설명·생성자) · Membership(user·project·role) · ProjectToken(project·token·revoked) · ProjectModule(project·모듈명).

## 2. 기능 2 — 요구사항 검토

범위: 고객 요구서를 등록하고 AI로 불명확·상충을 검토해 확정, 버전으로 관리.

| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| FR-2-01 | 요구사항 등록 | 고객 요구서(.docx) 업로드→표 파싱, 또는 직접 추가. 등록 시 상태=접수 | P0 |
| FR-2-02 | 요구사항 목록 | 분류별 그룹, 상태·버전·담당자 표시, 담당자 필터 | P0 |
| FR-2-03 | AI 검토 | 본문에서 불명확(7종 유형)·상충 검출 + 명확화 제안 | P0 |
| FR-2-04 | 수정·확정 | 제안 반영·직접 편집 → 변경 사유와 함께 확정 → 새 버전 | P0 |
| FR-2-05 | 버전 이력 | 확정마다 버전(Semver) 부여, 커밋형 이력·버전 diff | P0 |

상태값: 접수 → 검토중 → 확정 → (수정) 변경중 → 재확정 · 보류.

---

## 3. 기능 3 — 산출물 도출

범위: 확정 요구사항에서 개발 이슈와 문서를 도출하고 추적한다.

| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| FR-3-01 | 개발 이슈 도출 | 확정 요구사항 1건 → 개발 이슈(티켓) N개 자동 도출 | P0 |
| FR-3-02 | 4종 도출 | 이슈마다 SWVOC·기능 요구사항·비기능 요구사항·Detail Design 초안 생성 | P0 |
| FR-3-03 | 협업 완성 | AI 초안→사람 확정 / 사람 직접 초안→AI 완성 | P0 |
| FR-3-04 | 산출물 편집 | 편집·확정. 기능 요구사항의 동작 정의 = 선행조건·시나리오·후행조건 | P0 |
| FR-3-05 | 추적 링크 | 요구사항 ↔ 개발 이슈 ↔ 산출물을 ID로 연결, 변경 영향 조회 | P0 |
