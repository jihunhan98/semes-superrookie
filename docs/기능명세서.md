## 2. 기능 2 — 산출물 도출 (개요, 이후 상세화)

**도출 구조**: 확정 요구사항 1개 → **개발 이슈(티켓) N개**(1~N), 개발 이슈 1개 → **SWVOC·기능 요구사항·비기능 요구사항·Detail Design 각 1개(1:1)**.

| ID | 기능 | 설명 | 우선 |
|---|---|---|---|
| FR-2-01 | 개발 이슈 도출 | 확정 요구사항에서 개발 이슈(티켓) N개 자동 생성 | P0 |
| FR-2-02 | 4종 산출물 도출 | 개발 이슈 1개마다 SWVOC·기능/비기능 요구사항·Detail Design 각 1개 초안 생성 | P0 |
| FR-2-03 | 작성 주체 구분 | 항목별 AI 초안/사람 표시(판단 기준) | P0 |
| FR-2-04 | 산출물 편집 | 개발 이슈 본문 및 4종 초안을 사람이 편집·확정 | P0 |
| FR-2-05 | 동작 정의 표 | 기본·변형·예외 × 선행·후행·시나리오(9행) | P0 |
| FR-2-06 | REQ 링크 | 개발 이슈·산출물에 근거 REQ-ID 연결 | P0 |

**개발 이슈(티켓)**: 부모. 본문 3카테고리(요구사항 접수·개발·변경점 설계). **하위 4종**: SWVOC · 기능 요구사항 · 비기능 요구사항 · Detail Design. (구조·작성 주체는 [DESIGN §4](../DESIGN.md) 참조)
