# 변경 영향 · 코드 근거 · 산출물 검증 구현

2026-10-07 / semes

## 사용 순서

1. 최신 semes 브랜치 전체를 받습니다. 기존 `.env`와 `.venv`를 유지합니다.
2. 이번 변경에는 소스 구문 분석 의존성이 추가되었습니다. **기존 AI 가상환경에서 한 번** `python -m pip install -r requirements.txt`를 실행합니다(ai-model 폴더 기준). 폐쇄망에서는 해당 Python 버전/Windows 아키텍처에 맞는 requirements의 wheel을 반입해 설치합니다. venv를 새로 만들 필요는 없습니다.
3. 기존 `run-all.bat`로 실행합니다. 프론트는 함께 갱신된 `frontend/dist/standalone`을 사용하므로 사용자 PC에서 npm install/build가 필요하지 않습니다. 기존 V002 이상 스키마의 AI_JOBS/AI_TASKS/KNOWLEDGE_ENTRIES를 사용하며 **DB 초기화나 테이블 추가는 없습니다.**
4. 프로젝트의 **변경 영향 · 코드 근거** 메뉴에서 실제 VCS/장비 SW 소스를 버전명과 함께 등록합니다. C++(.cpp/.cc/.cxx/.h/.hpp), Java, C#, Python을 지원합니다. 최대 100파일/전체 2MB입니다. 폴더 선택은 지원하는 소스 확장자만 수집합니다.
5. 요구사항 등록·AI 수정 검토·확정 시 영향 작업이 생성됩니다. 상단 알림에서 영향 목록으로 이동해 변경 전후 값, 대상 원문, 이유와 수정 제안을 확인합니다. 읽음은 수정 완료를 의미하지 않습니다.
6. 개발 이슈 도출 후 산출물을 생성합니다. 기존 문서는 AI 재검토로 새 근거 정책을 적용합니다. 검토 화면의 **AI 누락 검토**로 원자 요구사항과 개발 이슈·문서의 연결을 봅니다.

## 구현

- 영향 작업은 기존 영속 작업 큐를 사용합니다. 신규/변경 내용, 전체 요구사항과 상태·버전, 입력 해시를 저장합니다. 같은 요청은 중복 생성하지 않습니다. 실패는 재시도되며 최종 실패와 영향 없음을 구분합니다.
- 전체 요구사항 각각에 IMPACT/NONE/UNKNOWN 판정이 있어야 결과를 수용합니다. 변경 전후 값·대상 구절이 원문에 없는 결과는 실패 처리합니다.
- 결과 조회 시 입력 해시가 현재 프로젝트와 다르면 STALE로 표시합니다. 재분석 버튼으로 최신 스냅샷 기준 작업을 생성합니다. 미확정 입력은 예상 영향으로 표시합니다.
- CODE/IMPACT/IMPACT_READ/COVERAGE는 기존 KNOWLEDGE_ENTRIES의 source_type으로 저장합니다. 읽음은 사용자별로 기록합니다. 코드 소스는 스냅샷으로 보존하며 등록한 최신 묶음을 사용합니다.
- Tree-sitter 문법 트리로 실제 클래스, namespace/package, 필드, 메서드 시그니처와 본문, 선언된 상속, 호출 표현식을 추출합니다. 업로드한 소스를 실행하지 않습니다.
- AI는 등록 심볼 ID를 참조하는 diagramModel을 반환합니다. 존재하지 않는 클래스/메서드를 거절하고 검증된 모델에서 Mermaid를 렌더링합니다. 변경 클래스는 강조하고 TO-BE 관계는 제안으로 표시합니다.
- 개발 이슈 도출 시 AI가 현상/개선 요구·완료 기준/범위/제약/변경 전후 본문을 채웁니다. 순서·제목만 변경하면 기존 ID와 링크를 유지합니다. 실제 분할/병합은 새 ID와 기존 lineage를 사용합니다. 표시 ID는 DB ID 기반 DEV-000123 형태입니다.
- 산출물 생성 입력에 이슈 본문과 전체 요구사항, 코드 근거를 추가합니다. 필드별 원문 evidence, 수치·단위·비교 연산자 검사, 코드 심볼 검사 결과를 표시합니다.
- 저장/개별 확정 시 서버가 근거를 다시 검사합니다. 브라우저가 보낸 GROUNDED 표시만 신뢰하지 않습니다. 전체 확정 전에도 전체 요구사항/이슈/산출물 누락·일관성 검토를 실행합니다.
- AI 누락 검토는 모든 원문을 원자 항목이 덮는지, 실제 이슈 ID와 문서 필드·구절을 참조하는지 검증합니다. 미연결, 누락, 수치 근거 부족과 AI 우려사항이 남으면 전체 확정을 막습니다.
- 회원가입은 로그인과 동일한 디자인을 적용했습니다. 신규 요구사항과 AI 재검토 입력은 파란색/둥근 카드와 입력창으로 통일했습니다.

## API

기존 API처럼 프로젝트 멤버 userId를 확인합니다. base: `/api/projects/{projectId}/insights`, 각 요청에 `?userId=...`.

| 메서드 | 경로 | 동작 |
|---|---|---|
| GET | /impacts | 영향 작업·결과·사용자별 읽음 상태 |
| POST | /impacts/{jobId}/read | 읽음 기록 |
| POST | /impacts/{jobId}/retry | 실패 재시도 또는 만료 입력 재분석 |
| GET | /code | 현재 소스 스냅샷 |
| POST | /code | `{version, files:[{path,content}]}` 등록·구문 분석 |
| GET | /coverage/{reqId} | 최근 누락 검토와 만료 여부 |
| POST | /coverage/{reqId} | 현재 이슈·산출물 기준 AI 누락 검토 |

AI 서버 추가 경로: `/code/index`, `/impact`, `/issues/enrich`, `/coverage`, `/artifacts/validate`. 기존 `/artifacts/generate`는 reqKey/issueContent/codeContext를 추가로 받습니다.

## 검증과 한계

- Python 단위/계약 테스트: 소스 4개 언어, C++ 별도 구현 파일, 잘못된 심볼·구절·문서 연결, SOC 수치/경계 변경, 누락 판정, AI 실패, 입력 상한, 저장 시 재검증.
- Java 단위 테스트: 영속 작업 입력, 중복 요청 방지, 만료 결과, 프로젝트 접근 제한. 이 환경에서는 JDK 17 호환 컴파일/테스트를 사용했습니다. 프로젝트의 Java 21 설정은 유지했습니다.
- 프론트 타입 검사·기존 테스트·production 빌드 및 standalone 패키징. 브라우저 검사: 회원가입/등록/영향 표시·대상 이동/읽음/코드 화면/모바일. 브라우저의 백엔드 데이터는 테스트 응답으로 검증했습니다.
- Mermaid 클래스/AS-IS/TO-BE 파싱과 렌더링 확인.
- **실제 사내 LLM 및 Oracle 연결은 이 환경에서 검증하지 못했습니다.** 현장 소스를 등록한 후 실제 요구사항으로 영향 분석과 산출물 재검토를 확인해야 합니다.
- 정적 구문 분석은 동적 바인딩·매크로·이벤트/콜백의 실제 실행 순서를 확정하지 못합니다. AS-IS에도 이 한계를 표시합니다. 새로운 클래스는 기존 구현으로 꾸며 그리지 않으며 설명의 신규 제안으로 남깁니다.
- 전체 입력은 `AI_MAX_CONTEXT_CHARS`(기본 120000자) 상한을 검사합니다. 초과 시 요구사항을 생략하지 않고 오류를 표시합니다. 모델 토큰 한도는 제공자 설정에 맞춰 별도 조정해야 합니다.
- 이번 영향 분석은 요구사항 간 알림·수정 제안까지입니다. 문서/코드 자동 수정·배포 및 실제 개발 완료 판정은 수행하지 않습니다.
